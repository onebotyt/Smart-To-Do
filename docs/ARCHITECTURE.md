# Architecture

## Layers (top depends on bottom)
1. **Presentation** — screens, floating panel UI, settings, widgets (`lib/features/*/…_page.dart`)
2. **Shared application logic** — controllers/state, validation, preferences (`lib/features/*/…_controller.dart`)
3. **Data** — SQLite, repositories, change log (`lib/data/`)
4. **Connectivity** — discovery, pairing, secure transfer (`lib/features/sync/`, later)
5. **Native platform adapters** — Android, Windows, iOS, macOS, Linux (`lib/platform/` + OS folders)

Feature code calls **Dart interfaces**, never platform channels directly. Example:
```dart
abstract class ClipboardService {
  Stream<String> get onLocalCopy;
  Future<void> writeText(String text);
}
// lib/platform/android/..., lib/platform/windows/... implement it
```

## Folder layout (target)
```
lib/
  app/            app shell, theme, routing
  core/           capabilities, utils
  data/
    database/     AppDatabase, migrations
    models/       Task, Device, ...
    repositories/ TaskRepository, ...
  features/
    tasks/ categories/ reminders/ sync/ clipboard/ floating_panel/ widgets/ devices/ settings/
  platform/       interfaces + per-OS implementations
android/ windows/ ios/ macos/ linux/   (generated by flutter create; native code goes here)
docs/  test/
```
State management: `provider` + `ChangeNotifier` (keep it simple; revisit only with approval).

## Data model (v1 schema)
`tasks`: id (UUID v4), title, notes, due_at (epoch ms UTC), priority 0-2, category, completed,
recurrence (none/daily/weekly), created_at, updated_at, revision, device_id, deleted (tombstone).
`change_log`: seq, task_id, op (create/update/delete), revision, device_id, at, synced.
`meta`: key/value (holds this install's device_id).

Invariant: every write to `tasks` also appends a `change_log` row in the same transaction
(implemented in `TaskRepository._save`). Deletes are soft (tombstone).

## Native integration plan
- Android: Kotlin foreground service + overlay window (`SYSTEM_ALERT_WINDOW`), AppWidgetProvider reading a local cache, clipboard listener in a foreground service. Bridge via MethodChannel/EventChannel.
- Windows: always-on-top window + system tray, native clipboard listener (`AddClipboardFormatListener`), launch-at-startup. Prefer maintained Flutter plugins (e.g. window/tray managers) before custom C++.
- Keep each native piece small, behind an interface, with a documented permission list.
